## 주요 업무 및 상세 역할

### 아키텍처 설계 및 IaC

- 간헐 트래픽 사내 도구에서 **비용의 지배 요인은 트래픽이 아니라 유휴 시간의 상시 과금**이라는 분석을 근거로,
  상시 실행 리소스(EC2·RDS·OpenSearch·ALB)를 전면 배제한 서버리스 아키텍처 설계
- 추천 서비스와 피드백 서비스의 **Terraform 스택을 분리** — 배포 주기·인증 방식·장애 영향 범위가 달라,
  한쪽 배포가 다른 쪽을 건드리지 않도록 격리
- Terraform 모듈 9종으로 dev · prod · prod-survey **3개 환경을 코드화**, 타 계정 복제 배포가 가능한 구성

| 구분 | 배포 리소스 |
|------|------|
| 컴퓨트 | Lambda ×7 (추천 6 + 피드백 1, 전부 Node.js 22) |
| API | REST API ×2 · WebSocket API ×1 |
| 데이터 | DynamoDB ×5 · S3 ×2 |
| 프론트 | CloudFront ×3 (추천 1 · 피드백 2, 전부 OAC) |
| 인증 | Cognito ×1 (추천 전용) · 피드백은 명단 대조 방식 |
| AI | Bedrock ×2 (Titan Embed v2 · Claude 3 Haiku) |
| 운영 | IAM 역할 4종 · CloudWatch 로그그룹 7종 |

### 유사상품 추천 AI 파이프라인

- 상품 마스터 **30,006건**을 Bedrock Titan Embed v2로 벡터화(1,024차원).
  L2 정규화를 적용해 **이후 내적만으로 코사인 유사도**를 얻도록 설계
- 벡터를 `embeddings.bin`(Float32 117MB)으로 S3에 적재하고, 추천 Lambda가 **콜드스타트에 1회 로드해 재사용**
- **하드룰 8요소 가중합**으로 MD의 실무 판단 기준을 정량화 —
  세분류 일치 1.698 / 색상 1.366 / 재질 1.166 / 특징 1.048 / 단가 0.934 / 입수 0.737 / 크기 0.655 / 품명 0.397
  (가중치 합 8.001로 0~1 정규화). **"결측은 0점"** 원칙으로 데이터 부재가 유리하게 작동하지 않도록 설계
- **하이브리드 블렌딩** — `최종점수 = 0.7 × 하드룰(정규화) + 0.3 × 임베딩 코사인`.
  임베딩 로드 실패 시 하드룰 단독으로 자동 폴백
- 모양 유사도(양쪽 확정 시에만 가점) · 향 카테고리 전용 가중 · 소싱 경로가 다른 카테고리 제외 등 판정 규칙 추가

### 응답 속도 · 비용 설계

- LLM이 추천 사유를 실시간 생성하면 1회에 수 초 소요 → **배치에서 전량 사전 생성 후 S3 적재**,
  요청 시에는 조회해 붙이는 구조로 전환. 결과적으로 **실시간 경로의 Bedrock 호출 0건**
- 3만 SKU 전체 쌍(약 4.5억)이 아니라 **동일 소분류(594종) 내 쌍만** 계산해 계산량을 수백분의 1로 축소하고,
  비싼 LLM 호출은 **상품당 상위 10쌍**으로 제한
- 사유 생성 배치는 15건 동시 호출 · 300건마다 체크포인트 · 4개 샤드 병렬로 **중단·재시작에 안전한 구조**
- **"검색을 조회로 바꾸면 검색 엔진은 필요 없다"** — 월 단위로만 바뀌는 데이터 특성에 맞춰 벡터 검색 엔진을 배제
  (S3 월 $0.02 vs OpenSearch 최소 구성 월 $25~100+) → **유휴 시 월 인프라 비용 $1 미만**

### 추천결과 피드백(설문) 서비스

- 추천 품질을 현장에서 검증하기 위한 설문 서비스를 신규 설계·구축
- **로그인리스 2단 검증** — 계정 발급 없이 매장코드 + 담당자 사번을 등록 명단과 대조 (등록 매장 약 1,341개)
- 후보 상품에 1~3순위 부여 + 선정 사유 다중 선택, 임시저장/제출, 마감기한 제어
- **결정론적 분산배정** — 재현 가능한 시드 기반 셔플로 참여자별 문항을 배정하되 문항 커버리지를 고르게 분산
- 관리자 화면에서 진행현황 · 미제출 명단 · 응답 CSV 내보내기 제공
- **추천 → 현장 피드백 → 로직 반영**의 개선 루프를 구성

### 평가 체계 및 품질 게이트

- **MD 정답셋 13,417쌍 전량**을 기준으로 한 오프라인 평가 파이프라인 운영
- 로직 개편 전후 비교로 **Hit@5 2.9% → 9.3% (3.2배)** 개선을 확인하고,
  기여 요인을 분해해 **최대 기여가 상품 마스터 확장(+5.4p)** 임을 규명
- 블렌딩 비율을 정답셋 기반 오프라인 평가로 탐색해 0.7 : 0.3 채택
- **회귀 테스트 57건** 전량 통과를 배포 조건으로 운영하고,
  매 실행마다 **배포 아티팩트와 테스트 대상 코드를 md5로 대조**해 "테스트한 코드 = 배포된 코드"를 보증

### 운영 및 고객 역량 이관

- 고객사 계정 프로덕션 배포·운영 직접 수행
- 초기 배포 잔재(미사용 REST API·WebSocket API·Cognito 풀)를 감사로 식별해 정리 대상으로 목록화
- 전량 재임베딩이 Lambda 최대 실행시간을 초과하는 것을 실측으로 확인,
  이벤트 트리거 동시성을 차단해 사고를 예방하고 대량 처리는 오프라인 배치로 경로 분리
- **코드 상수로 고정돼 있던 하드룰 가중치·블렌딩 비율·추천 개수를 관리자 화면으로 노출** —
  값 변경 시 정규화 분모까지 함께 재계산되도록 처리해 고객이 직접 로직을 튜닝할 수 있게 이관
- 비전공 고객(MD·관리자) 대상 분석 용어집·시각화 보고서 제작 및 단계별 교육 진행 →
  고객사가 자체적으로 로직 개편을 주도하고 타 조직 확산을 추진하는 단계에 도달
